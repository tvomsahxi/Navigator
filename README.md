# Navigator — セキュリティ規格ナビゲータ

CIRT／PSIRT がポータルとして使うことを想定した、サイバーセキュリティの規格・
政府文書の横断参照サイト。日本・米国・EU・国際規格の **97 文書 / 572 章** を、
章レベルの粒度で、事業ドメインと業務カテゴリの両軸から引ける。

ビルド不要。`index.html` をブラウザで開けばそのまま動く（`file://` でも可）。

```
open index.html
```

単一ファイルで配布したい場合:

```
node tools/build-single.js   # -> dist/navigator.html
```

---

## 4つのビュー

| ビュー | 用途 |
|---|---|
| **文書一覧** | 地域・種別・ドメイン・業務カテゴリ・全文検索で絞り込む。行を開くと章立てと関連文書が出る |
| **業務カテゴリ** | 11カテゴリの MECE な定義。成果物・担当・境界の判定ルール付き |
| **ドメイン別** | 事業ドメイン × 業務カテゴリの文書数マトリクス。カバレッジの穴を探す |
| **文書間の関係** | 上位／詳細化／実装手段／国内適用などの関係を種類別に一覧 |

キーボード: `/` で検索へ、`Esc` で詳細を閉じる。

### 事業ドメイン（10区分）

三菱電機の事業セグメントに対応させた区分。
`PWR` 電力・エネルギー / `RAIL` 交通システム（鉄道）/ `DEF` 防衛・宇宙 /
`FA` 産業オートメーション / `AUTO` 自動車機器 / `BLD` ビルシステム /
`LIFE` 空調冷熱・家電・住宅IoT / `IT` ITソリューション・DC /
`SEMI` 半導体・デバイス / `CORP` 全社共通

### 業務カテゴリ（11区分・MECE）

**分割軸は「その活動が何を成果物として生み出すか」**。企画から廃棄までを4クラスタで覆う。

| クラスタ | カテゴリ |
|---|---|
| 統制 | `GOV` ガバナンス・組織体制 / `LEG` 法規制対応・適合性 / `RSK` リスクマネジメント |
| 構築 | `SCM` サプライチェーン・調達 / `DEV` セキュア開発・製品セキュリティ / `OPS` システム運用・技術的対策 |
| 運用 | `MON` 監視・検知・脅威インテリジェンス / `IRS` インシデント対応・脆弱性ハンドリング・報告 / `BCP` 事業継続・復旧 |
| 基盤 | `HRD` 人材育成・意識向上・演習 / `ASR` 保証・監査・継続的改善 |

隣接カテゴリには境界の判定ルール（tiebreak）を定義してある。例えば
「守りを立てる」のが `OPS`、「異常を見る」のが `MON`。同じログでも取得・保全の
設計は `OPS`、分析と検知は `MON` に落ちる。

> **MECE なのは「業務」の分類であって「文書」の分類ではない。**
> 1つの文書が複数カテゴリにまたがるのは正常。個々の業務活動が一意に決まることを保証している。

## データの持ち方

```
data/
  taxonomy.js          地域・種別・ドメイン・カテゴリ・関係種別の定義
  documents-int.js     国際規格
  documents-us.js      米国
  documents-eu.js      EU
  documents-jp.js      日本
```

各ファイルは `window.NAV.documents` に追記するだけの素の JS。1文書のかたち:

```js
{
  id: "iec62443-4-1",
  short: "IEC 62443-4-1:2018",        // 表・関係図で使う短縮名
  title: "セキュア製品開発ライフサイクル要求事項",
  orig:  "Secure product development lifecycle requirements",
  issuer: "IEC TC 65/WG 10",
  region: "INT",  type: "STD",  version: "Ed.1",  year: 2018,
  binding: "任意（IECEE CB 等の認証制度あり）",   // 拘束力
  url: "https://webstore.iec.ch/publication/33615",
  summary: "…",                       // 何のための文書か
  scope:   "…",                       // 誰に適用されるか
  domains: ["FA", "PWR", "BLD"],
  cats:    ["DEV", "GOV", "IRS"],     // 文書全体としての主用途
  chapters: [
    { no: "SM", title: "実践1: セキュリティ管理", cat: ["GOV","DEV"], note: "…" }
  ],
  rel: [
    { to: "iec62443-4-2", kind: "ref", note: "プロセスと製品機能の対" }
  ],
  verify: "…"                         // 任意。原典確認が要る箇所を書くと ! が付く
}
```

**カテゴリは2層で持つ。** `cats` は文書全体の主用途（濃い印）。章に付けた `cat` は
起動時に合成され、`cats` に無いものは副次カテゴリ（薄い印）として扱われる。
絞り込みは合成後の集合に対して効くので、「章単位でしか該当しない文書」も拾える。

### 関係の向き

`rel` は **有向**。`kind` の意味は「この文書から見た相手」:

| kind | A → B の意味 |
|---|---|
| `parent` | B は A の**上位**要求元 |
| `detail` | B は A を**詳細化**した文書 |
| `impl` | B は A を満たすための**実装手段** |
| `local` | B は A の**国内適用**版 |
| `ref` / `align` | 参照 / 対応関係（無向に近い） |
| `supersede` | 版の更新関係 |

`parent` と `detail`、`impl` と被実装は逆向きの対。**同じ kind の逆向きエッジが
両方あると矛盾**になるので、下の検証で落ちる。逆方向は自動生成されて詳細パネルに
「◀ 被参照」として出るため、片側だけ書けばよい。

### 検証

データを足したら必ず通す:

```
node tools/validate.js     # 必須項目・未定義コード・壊れた参照・関係の向きの矛盾
```

## 正確性についての注意

各文書の章立ては**実務で引くための要約**であって、原典の目次の逐語的な写しではない。
特に次のものは節番号や版数が改訂で動く:

- 公開情報が限られる国内の業界ガイドライン（JESC Z0004、鉄道GL、防衛産業基準 など）
- 章立てを大きく変えた改訂版（IEC 62443-2-1 Ed.2、NIST SP 800-61 Rev.3 など）
- 制度設計が進行中のもの（サイバー対処能力強化法、CMMC の適用スケジュール など）

該当する文書には `verify` を書いてあり、一覧と詳細パネルに `!` が出る。
**適合性の判断・監査対応・契約の根拠に使う場合は、必ず `url` の原典に当たること。**

収録しているのは各文書の書誌情報・構成の要約・相互関係であり、規格本文は含まない。
